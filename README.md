# Marketplace Analytics

Анализ поведения пользователей маркетплейса, сегментация товаров и прогноз взаимодействий на следующий день.

[Открыть ноутбук с результатами](analysis.ipynb)

## Цель

Исследовать распределение пользовательской активности и внимания к ассортименту, построить последовательную воронку и проверить, улучшают ли модели машинного обучения простые прогнозы будущей активности.

## Данные

[T-ECD, small/marketplace](https://huggingface.co/datasets/t-tech/T-ECD), семь последовательных шардов `01082–01088`.

| Показатель | Значение |
| --- | ---: |
| События | 3 515 262 |
| Пользователи | 223 443 |
| Товары в каталоге | 2 325 409 |
| Товары с событиями | 185 831 |
| Период наблюдения | 7 дней |

События: `view`, `click`, `clickout`, `like`. Ценовой показатель обезличен; покупки, выручка и показы выдачи не наблюдаются. Источник и условия использования данных указаны в карточке датасета.

## Методология

- Проверка качества, пропусков и ключей, подготовка данных в Pandas.
- EDA: динамика DAU, часовая активность, повторная активность, категории, концентрация взаимодействий.
- Последовательная воронка на уровне пользователь–товар–день.
- KMeans для активных товаров; выбор числа кластеров по silhouette с ограничением минимальной доли сегмента.
- Прогноз на следующий день по двум предшествующим дням. Train: три целевых дня, validation: один, test: один. Порог класса и выбор модели определяются без использования тестовых результатов в исходном эксперименте.
- Сравнение способов агрегации на трёх объёмах данных, по пять замеров.

## Результаты полного запуска

### Аналитика

- Повторная активность (события минимум в два дня): **45,6%** пользователей. Это не когортный retention.
- Охват каталога наблюдаемыми событиями: **7,99%**.
- На верхний 1% активных товаров приходится **81,71%** событий.
- Медиана событий на пользователя: 6, среднее: 15,73.
- У 41,56% товаров отсутствует категория.

### Воронка

События должны идти строго по времени в пределах дня. Это не воронка покупок.

### Сегментация

### Классификация

Цель: не менее двух взаимодействий с товаром на следующий день среди товаров, активных в предшествующие два дня.

| Модель / baseline | AP (test) | ROC-AUC (test) |
| --- | ---: | ---: |
| Константная вероятность | 0,1401 | 0,5000 |
| Ранжирование по активности предыдущего дня | 0,5400 | 0,7888 |
| HistGradientBoostingClassifier | 0,6266 | 0,8364 |

F1 = 0,5936; precision = 0,6251; recall = 0,5651. Порог 0,325 выбран по validation.

### Регрессия

Цель — количество событий следующего дня. На validation сравнивались шесть методов:

| Метод | MAE (validation) |
| --- | ---: |
| Наивный прогноз с корректирующим коэффициентом | **2,9586** |
| Наивный прогноз по предыдущему дню | 3,1677 |
| Среднее за два предыдущих дня | 3,3518 |
| Градиентный бустинг с логарифмированием целевой переменной | 5,1873 |
| Медиана обучающей выборки | 5,7347 |
| Среднее обучающей выборки | 10,5888 |

Наивный прогноз использует число событий предыдущего дня без изменений. В скорректированном варианте это число умножается на коэффициент 0,85, подобранный на валидационной выборке: `0.85 * last_day`.

| Метод | MAE (test) | RMSE (test) | R² (test) |
| --- | ---: | ---: | ---: |
| Наивный прогноз по предыдущему дню | 2,606 | 33,840 | 0,856 |
| Наивный прогноз с корректирующим коэффициентом | **2,375** | **31,357** | **0,877** |

Снижение MAE на 8,9% относительно наивного прогноза по предыдущему дню. В первоначальном эксперименте Poisson-бустинг дал численно нестабильный прогноз и был отклонён. Более устойчивый бустинг с логарифмированием цели не превзошёл простые методы на validation. Повторная проверка использует ранее изученный тестовый день, поэтому результат исследовательский; необходим новый период для независимой оценки.

## Практическое применение и ограничения

Результаты позволяют приоритизировать изучение видимости ассортимента, проверять гипотезы о пользовательских путях и ранжировать ранее активные товары для мониторинга. Для причинных выводов и оценки коммерческой эффективности нужны показы, заказы, выручка и эксперименты. История короткая, тестовый период состоит из одного дня, многие товары имеют всего одно событие. Прогноз не охватывает новые и давно неактивные товары.

### Подготовка входных файлов с нуля

Если сохранённых Parquet-файлов нет, один раз загрузите нужные шарды из источника. Понадобится несколько гигабайт дискового пространства: исходный `items.pq` содержит также эмбеддинги. Установите `huggingface_hub` (`pip install huggingface_hub`). В рабочей папке выполните:

```python
import pandas as pd
from huggingface_hub import hf_hub_download

repo = "t-tech/T-ECD"
root = "dataset/small/marketplace"
event_cols = ["timestamp", "user_id", "item_id", "subdomain", "action_type", "os"]
item_cols = ["item_id", "brand_id", "category", "subcategory", "price"]

def download(path):
    return hf_hub_download(repo, path, repo_type="dataset")

parts = [
    pd.read_parquet(download(f"{root}/events/{d:05d}.pq"), columns=event_cols)
    for d in range(1082, 1089)
]
pd.concat(parts, ignore_index=True).to_parquet("events.parquet", index=False)
del parts
pd.read_parquet(download(f"{root}/items.pq"), columns=item_cols).to_parquet(
    "items.parquet", index=False
)
```

Ревизия источника в исходном запуске не была зафиксирована. Поэтому восстановление данных из обновлённого источника и новые версии библиотек могут изменить результаты. В Colab сохраните подготовленные файлы локально перед завершением сессии.
